Switchr

Technologies and approaches behind Switchr

Switchr is a keyboard-driven window switcher for Windows: a tray app that renders a GPU-composited overlay with live thumbnails on a hotkey. It's built in C++17 directly on Direct3D 11, DirectComposition, and Direct2D — no game engine, no UI toolkit — plus a set of Win32/DWM mechanisms (WinEvent hooks, live thumbnails, cloak checks) that most Alt-Tab clones skip. Here's how the pieces fit together, with links straight to the source.

The rendering stack: D3D11 device behind a composition swap chain

The overlay window doesn't own a normal HWND-backed swap chain — it's composited. Renderer creates a D3D11 device with BGRA_SUPPORT, wraps it in a DCompositionDevice, and creates a swap chain for composition rather than for the window directly, attaching it to a DCompositionVisual that's the actual thing DWM composites to screen: Switchr/src/Renderer.cpp#L29-L34 and L68-L81. Direct2D then gets a device context created directly on top of the same DXGI device, so D2D draws land straight into the swap chain's back buffer with no extra copy (L83-L90).

Fade in/out isn't driven by a UI-thread timer. IDCompositionVisual has no opacity property of its own, so an effect group is attached to carry it, and AnimateOpacity() hands DComp a linear ramp via IDCompositionAnimation::AddCubic — once committed, the compositor advances the fade on its own thread, independent of whatever the app thread is doing: Switchr/src/Renderer.cpp#L188-L205. That's what keeps the overlay's fade smooth even if the app thread is momentarily busy laying out tiles or rescoring a search.

Live thumbnails via DWM, not screenshots

The tile grid doesn't grab bitmaps of other windows — it registers each visible window as a DWM thumbnail source with DwmRegisterThumbnail and lets the compositor stream the live content directly into a destination rectangle on the overlay: Switchr/src/Overlay.cpp#L852-L866. Because DWM doesn't clip a thumbnail to the destination window's bounds, a tile that's only half-scrolled into view would otherwise bleed over the search box — so before every layout pass Switchr explicitly hides any thumbnail whose tile isn't fully inside the visible viewport, rather than relying on clipping that doesn't exist: L868-L894.

MRU ordering from one event hook, not polling

Most-recently-used ordering comes from a single SetWinEventHook on EVENT_SYSTEM_FOREGROUND — every time a top-level window becomes the foreground window, it gets stamped with the next value of a monotonically increasing counter, and the tile grid just sorts by that stamp: Switchr/src/MruTracker.cpp#L8-L19. On startup there's no history yet, so ranks are seeded once from the current z-order — EnumWindows already yields windows topmost-first, so the front-most window just gets the highest initial rank: L26-L36. No polling, no periodic rescan — the whole tracker is an event callback and a hash map.

Which windows even count as "Alt-Tab windows"

Deciding what belongs in the switcher at all turns out to be its own small algorithm. Switchr reimplements the classic rule Windows itself uses for Alt-Tab: a window only qualifies if it's the last active visible popup of its own owner chain, walked via GetAncestor(GA_ROOTOWNER) and GetLastActivePopup — which is what correctly excludes owned dialogs and tool palettes while still surfacing the right window for apps that keep a hidden main frame behind a visible child: Switchr/src/WindowList.cpp#L25-L51. On top of that it filters WS_EX_TOOLWINDOW and windows DWM reports as DWMWA_CLOAKED — the flag UWP apps and windows parked on an inactive virtual desktop carry while technically still "visible" by every other Win32 test.

Activating the chosen window goes through the standard workaround for SetForegroundWindow's focus-stealing restriction: temporarily AttachThreadInput to whatever thread currently owns the foreground window, so Windows treats the activation as coming from the already-focused thread instead of an unrelated background process, then detach immediately after: Switchr/src/WindowList.cpp#L118-L139. A hung target window (IsHungAppWindow) skips all of that and just gets an async restore, since attaching thread input to a window that isn't pumping messages would hang the switcher too.

Search: multi-term AND matching with position-weighted scoring

Typing splits the query on whitespace into lowercase terms, and every term must appear in either the window title or the exe name for a window to survive at all — a genuine AND, not a fuzzy edit-distance match: Switchr/src/Overlay.cpp#L93-L115. Within that, the score rewards a term matching at position 0 heavily (a prefix match on the title outscores a mid-string match by more than 3:1), gives a smaller bonus for matching the exe name, and adds a mild bias toward shorter titles so that, all else equal, "Notepad" ranks above "Notepad — some/long/path/deep/in/a/tree.txt". Results are then sorted by score first and MRU rank as the tiebreaker, so among equally good text matches the window you touched most recently still wins: L735-L745.

Namespaces: hiding windows without the taskbar flicker

Switching a namespace means showing one set of windows and hiding another, batched through BeginDeferWindowPos/EndDeferWindowPos so the whole transition applies as one atomic update instead of a visible flash as windows disappear one by one: Switchr/src/Namespaces.cpp#L120-L136. Before that, every window involved gets DWMWA_TRANSITIONS_FORCEDISABLED set so DWM's own show/hide animation doesn't fight the deferred move, and it's restored right after — otherwise a whole workspace of windows animating in and out at once looks like the desktop falling apart rather than a clean switch: L102-L118.

New windows are auto-assigned to the active namespace via two more WinEvent hooks — EVENT_OBJECT_SHOW and EVENT_OBJECT_DESTROY — rather than any polling loop: Switchr/src/Namespaces.cpp#L418-L427. "Load and launch missing apps" (Ctrl+Shift+L) has to solve a timing problem: the process it just launched doesn't have a window yet, so its eventual window can't be assigned to a namespace synchronously. Instead the launch records a PendingAssign — expected exe name, target namespace, timestamp — with a two-minute TTL, and the next EVENT_OBJECT_SHOW for a matching exe consumes it and drops the entry if the launch never produced a window in time: Switchr/src/Namespaces.cpp#L173-L189.

The saved layout itself is a deliberately simple line-based UTF-8 format under %APPDATA%\Switchr\namespaces.txt — a ns<TAB>name line starts each namespace, and following app<TAB>path lines list its apps, with file order doubling as namespace order: Switchr/src/Namespaces.cpp#L162-L166.

Per-monitor DPI, properly

The app manifest declares PerMonitorV2 DPI awareness (Switchr/app.manifest), and the overlay reads GetDpiForWindow both on creation and on WM_DPICHANGED, so dragging the overlay's owning monitor setup around — or just opening it on a monitor at a different scale than the last one — keeps every DIP constant measurement (tile size, gaps, font size) crisp instead of blurry or mis-scaled. The overlay itself always opens on the monitor of the current foreground window, resolved through MonitorFromWindow, not wherever the mouse cursor happens to be: Switchr/src/Overlay.cpp#L555-L563.

No installer, no admin, one instance

The manifest requests asInvoker execution — Switchr never needs to elevate, which matters because a non-elevated Switchr can't AttachThreadInput to or activate a window owned by an elevated process, a real limitation the project accepts rather than asking users to run it as admin. A single named mutex enforces one running instance: Switchr/src/main.cpp#L140, and the whole thing ships as one exe with no install step — the tray icon and a RegisterHotKey global hotkey are the entire footprint on the running system.

The stack, in one place

  • C++17 directly on Win32 — no UI framework, no game engine.
  • Direct3D 11 + DirectComposition + Direct2D + DirectWrite for GPU-composited rendering, with server-side (compositor-thread) opacity animation.
  • DWM thumbnails (DwmRegisterThumbnail) for live tile previews instead of captured bitmaps.
  • WinEvent hooks (EVENT_SYSTEM_FOREGROUND, EVENT_OBJECT_SHOW/DESTROY) drive MRU tracking and namespace auto-assignment — no polling anywhere.
  • PerMonitorV2 DPI awareness declared in the app manifest, with live WM_DPICHANGED handling.
  • A hand-written multi-term search ranker (position-weighted, MRU-tiebroken) over window titles and exe names.
  • Plain line-based UTF-8 persistence for namespace layouts under %APPDATA% — no database, no serialization library.
  • asInvoker, single-instance via a named mutex, zero-install single exe.
