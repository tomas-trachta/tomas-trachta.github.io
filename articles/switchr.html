Switchr

Technologies and approaches behind Switchr

Switchr is a keyboard-driven window switcher for Windows: a tray app that renders a GPU-composited overlay with live thumbnails on a hotkey. It's built in C++17 directly on Direct3D 11, DirectComposition, and Direct2D — no game engine, no UI toolkit — plus a set of Win32/DWM mechanisms (WinEvent hooks, live thumbnails, cloak checks) that most Alt-Tab clones skip. Here's how the pieces fit together, with real snippets from the source (trimmed for length; // … marks an elision).

The rendering stack: D3D11 device behind a composition swap chain

The overlay window doesn't own a normal HWND-backed swap chain — it's composited. Renderer creates a D3D11 device with BGRA_SUPPORT, wraps it in a DCompositionDevice, and creates a swap chain for composition rather than for the window directly, attaching it to a DCompositionVisual that's the actual thing DWM composites to screen:

Switchr/src/Renderer.cppview file →
void Renderer::CreateDeviceResources() {
    CreateD3DDevice();
    CreateCompositionTarget();
    CreateD2D();
    CreateTextAndImaging();
}

void Renderer::CreateCompositionTarget() {
    ThrowIfFailed(DCompositionCreateDevice(dxgi_.Get(), IID_PPV_ARGS(&dcomp_)),
                  "DCompositionCreateDevice");
    ThrowIfFailed(dcomp_->CreateTargetForHwnd(hwnd_, TRUE, &dcompTarget_),
                  "CreateTargetForHwnd");
    ThrowIfFailed(dcomp_->CreateVisual(&dcompVisual_), "DComp CreateVisual");
    ThrowIfFailed(dcompTarget_->SetRoot(dcompVisual_.Get()), "DComp SetRoot");

    // IDCompositionVisual has no SetOpacity — opacity (static and animated)
    // goes through an effect group attached to the visual.
    ThrowIfFailed(dcomp_->CreateEffectGroup(&opacityEffect_), "DComp CreateEffectGroup");
    opacityEffect_->SetOpacity(1.0f);
    ThrowIfFailed(dcompVisual_->SetEffect(opacityEffect_.Get()), "Visual SetEffect");
}

Direct2D then gets a device context created directly on top of the same DXGI device, so D2D draws land straight into the swap chain's back buffer with no extra copy:

Switchr/src/Renderer.cppview file →
void Renderer::CreateD2D() {
    ThrowIfFailed(D2D1CreateFactory(
        D2D1_FACTORY_TYPE_SINGLE_THREADED, IID_PPV_ARGS(&d2dFactory_)),
        "D2D1CreateFactory");
    ThrowIfFailed(d2dFactory_->CreateDevice(dxgi_.Get(), &d2dDevice_), "D2D CreateDevice");
    ThrowIfFailed(d2dDevice_->CreateDeviceContext(
        D2D1_DEVICE_CONTEXT_OPTIONS_NONE, &d2dCtx_), "D2D CreateDeviceContext");
}

Fade in/out isn't driven by a UI-thread timer. IDCompositionVisual has no opacity property of its own, so an effect group is attached to carry it, and AnimateOpacity() hands DComp a linear ramp via IDCompositionAnimation::AddCubic — once committed, the compositor advances the fade on its own thread, independent of whatever the app thread is doing:

Switchr/src/Renderer.cppview file →
void Renderer::AnimateOpacity(float from, float to, double seconds) {
    if (!opacityEffect_ || !dcomp_) return;

    ComPtr<IDCompositionAnimation> anim;
    if (FAILED(dcomp_->CreateAnimation(&anim)) || !anim) {
        opacityEffect_->SetOpacity(to);
        dcomp_->Commit();
        return;
    }

    // Linear ramp: f(t) = from + ((to - from) / seconds) * t, ending at `seconds`.
    double slope = (seconds > 0.0) ? ((to - from) / seconds) : 0.0;
    anim->AddCubic(0.0, from, (float)slope, 0.0f, 0.0f);
    anim->End(seconds, to);

    opacityEffect_->SetOpacity(anim.Get());
    dcomp_->Commit();
}

That's what keeps the overlay's fade smooth even if the app thread is momentarily busy laying out tiles or rescoring a search.

Live thumbnails via DWM, not screenshots

The tile grid doesn't grab bitmaps of other windows — it registers each visible window as a DWM thumbnail source with DwmRegisterThumbnail and lets the compositor stream the live content directly into a destination rectangle on the overlay. Because DWM doesn't clip a thumbnail to the destination window's bounds, a tile that's only half-scrolled into view would otherwise bleed over the search box — so before every layout pass Switchr explicitly hides any thumbnail whose tile isn't fully inside the visible viewport, rather than relying on clipping that doesn't exist:

Switchr/src/Overlay.cppview file →
static void RegisterThumbnails(Overlay::State& s, HWND overlayHwnd) {
    UnregisterThumbnails(s);
    if (s.mode != Mode::Tiles) return;

    int n = (int)s.filtered.size();
    s.thumbs.assign(n, nullptr);
    for (int i = 0; i < n; ++i) {
        HWND src = s.all[s.filtered[i]].hwnd;
        HTHUMBNAIL th = nullptr;
        if (FAILED(DwmRegisterThumbnail(overlayHwnd, src, &th)) || !th) continue;
        s.thumbs[i] = th;
    }
    UpdateThumbnailLayout(s);
}

// Thumbs whose tile is not fully inside the viewport are hidden — DWM doesn't
// clip destination rects, so a half-scrolled thumb would overlap the search box.
static void UpdateThumbnailLayout(Overlay::State& s) {
    for (int i = 0; i < n; ++i) {
        // …
        bool fullyVisible = ((float)shifted.top    >= s.viewportTop) &&
                            ((float)shifted.bottom <= s.viewportBot);

        DWM_THUMBNAIL_PROPERTIES p{};
        p.dwFlags = DWM_TNP_RECTDESTINATION | DWM_TNP_VISIBLE |
                    DWM_TNP_OPACITY | DWM_TNP_SOURCECLIENTAREAONLY;
        p.rcDestination = shifted;
        p.fVisible      = fullyVisible ? TRUE : FALSE;
        DwmUpdateThumbnailProperties(s.thumbs[i], &p);
    }
}

MRU ordering from one event hook, not polling

Most-recently-used ordering comes from a single SetWinEventHook on EVENT_SYSTEM_FOREGROUND — every time a top-level window becomes the foreground window, it gets stamped with the next value of a monotonically increasing counter, and the tile grid just sorts by that stamp:

Switchr/src/MruTracker.cppview file →
HWINEVENTHOOK                       g_hook    = nullptr;
uint64_t                            g_counter = 0;
std::unordered_map<HWND, uint64_t>  g_ranks;

void CALLBACK FgHookProc(HWINEVENTHOOK, DWORD, HWND hwnd,
                         LONG idObject, LONG idChild, DWORD, DWORD) {
    if (!hwnd) return;
    if (idObject != OBJID_WINDOW || idChild != CHILDID_SELF) return;
    if (GetAncestor(hwnd, GA_ROOT) != hwnd) return;

    g_ranks[hwnd] = ++g_counter;
}

On startup there's no history yet, so ranks are seeded once from the current z-order — EnumWindows already yields windows topmost-first, so the front-most window just gets the highest initial rank:

Switchr/src/MruTracker.cppview file →
// EnumWindows yields top-to-bottom z-order; the topmost window is the most
// recently active one, so it gets the largest rank.
void SeedRanksFromZOrder() {
    std::vector<HWND> hwnds;
    hwnds.reserve(256);
    EnumWindows(CollectHwndProc, reinterpret_cast<LPARAM>(&hwnds));

    g_counter = static_cast<uint64_t>(hwnds.size()) + 1;
    uint64_t rank = g_counter;
    for (HWND h : hwnds) g_ranks[h] = rank--;
}

No polling, no periodic rescan — the whole tracker is an event callback and a hash map.

Which windows even count as "Alt-Tab windows"

Deciding what belongs in the switcher at all turns out to be its own small algorithm. Switchr reimplements the classic rule Windows itself uses for Alt-Tab: a window only qualifies if it's the last active visible popup of its own owner chain, walked via GetAncestor(GA_ROOTOWNER) and GetLastActivePopup — which is what correctly excludes owned dialogs and tool palettes while still surfacing the right window for apps that keep a hidden main frame behind a visible child. On top of that it filters WS_EX_TOOLWINDOW and windows DWM reports as DWMWA_CLOAKED — the flag UWP apps and windows parked on an inactive virtual desktop carry while technically still "visible" by every other Win32 test:

Switchr/src/WindowList.cppview file →
// The classic alt-tab ownership rule: a window qualifies only if it is the
// last active visible popup of its own owner chain.
bool IsLastActivePopupOfOwnerChain(HWND hwnd) {
    HWND walk = nullptr;
    HWND tryW = GetAncestor(hwnd, GA_ROOTOWNER);
    while (tryW != walk) {
        walk = tryW;
        tryW = GetLastActivePopup(walk);
        if (IsWindowVisible(tryW)) break;
    }
    return walk == hwnd;
}

bool IsCloaked(HWND hwnd) {
    BOOL cloaked = FALSE;
    return SUCCEEDED(DwmGetWindowAttribute(hwnd, DWMWA_CLOAKED, &cloaked, sizeof(cloaked)))
        && cloaked;
}

bool IsAltTabWindow(HWND hwnd) {
    if (!IsWindowVisible(hwnd)) return false;
    if (!IsLastActivePopupOfOwnerChain(hwnd)) return false;
    if (GetWindowLongPtrW(hwnd, GWL_EXSTYLE) & WS_EX_TOOLWINDOW) return false;
    if (IsCloaked(hwnd)) return false;
    if (GetWindowTextLengthW(hwnd) == 0) return false;
    return true;
}

Activating the chosen window goes through the standard workaround for SetForegroundWindow's focus-stealing restriction: temporarily AttachThreadInput to whatever thread currently owns the foreground window, so Windows treats the activation as coming from the already-focused thread instead of an unrelated background process, then detach immediately after:

Switchr/src/WindowList.cppview file →
void ForceForeground(HWND target) {
    if (IsHungAppWindow(target)) {
        if (IsIconic(target)) ShowWindowAsync(target, SW_RESTORE);
        return;
    }

    DWORD curThread = GetCurrentThreadId();
    HWND  fgWnd     = GetForegroundWindow();
    DWORD fgThread  = fgWnd ? GetWindowThreadProcessId(fgWnd, nullptr) : 0;

    bool attached = false;
    if (fgThread && fgThread != curThread && !IsHungAppWindow(fgWnd)) {
        attached = AttachThreadInput(curThread, fgThread, TRUE) != 0;
    }

    if (IsIconic(target)) ShowWindow(target, SW_RESTORE);
    BringWindowToTop(target);
    SetForegroundWindow(target);
    SetFocus(target);

    if (attached) AttachThreadInput(curThread, fgThread, FALSE);
}

A hung target window (IsHungAppWindow) skips all of that and just gets an async restore, since attaching thread input to a window that isn't pumping messages would hang the switcher too.

Search: multi-term AND matching with position-weighted scoring

Typing splits the query on whitespace into lowercase terms, and every term must appear in either the window title or the exe name for a window to survive at all — a genuine AND, not a fuzzy edit-distance match. The score rewards a term matching at position 0 heavily (a prefix match on the title outscores a mid-string match by more than 3:1), gives a smaller bonus for matching the exe name, and adds a mild bias toward shorter titles so that, all else equal, "Notepad" ranks above "Notepad — some/long/path/deep/in/a/tree.txt":

Switchr/src/Overlay.cppview file →
// -1 = no match.
int ScoreEntry(const WindowEntry& w, const std::vector<std::wstring>& terms) {
    if (terms.empty()) return 0;

    std::wstring title = ToLower(w.title);
    std::wstring exe   = ToLower(w.exe);

    int score = 0;
    for (const auto& t : terms) {
        size_t titlePos = title.find(t);
        size_t exePos   = exe.find(t);
        if (titlePos == std::wstring::npos && exePos == std::wstring::npos) return -1;

        int termScore = 0;
        if (titlePos == 0) termScore += 100;
        else if (titlePos != std::wstring::npos) termScore += 60 - std::min<int>(50, (int)titlePos);
        if (exePos == 0) termScore += 30;
        else if (exePos != std::wstring::npos) termScore += 15;
        score += termScore;
    }

    score += std::max(0, 40 - (int)title.size() / 4);
    return score;
}

Results are then sorted by score first and MRU rank as the tiebreaker, so among equally good text matches the window you touched most recently still wins:

Switchr/src/Overlay.cppview file →
struct Scored { int idx; int score; uint64_t mru; };
std::vector<Scored> hits;
for (int i = 0; i < (int)s.all.size(); ++i) {
    int sc = ScoreEntry(s.all[i], terms);
    if (sc >= 0) hits.push_back({ i, sc, Mru::Rank(s.all[i].hwnd) });
}

std::sort(hits.begin(), hits.end(),
    [](const Scored& a, const Scored& b) {
        if (a.score != b.score) return a.score > b.score;
        return a.mru > b.mru;
    });

Namespaces: hiding windows without the taskbar flicker

Switching a namespace means showing one set of windows and hiding another, batched through BeginDeferWindowPos/EndDeferWindowPos so the whole transition applies as one atomic update instead of a visible flash as windows disappear one by one. Before that, every window involved gets DWMWA_TRANSITIONS_FORCEDISABLED set so DWM's own show/hide animation doesn't fight the deferred move, and it's restored right after — otherwise a whole workspace of windows animating in and out at once looks like the desktop falling apart rather than a clean switch:

Switchr/src/Namespaces.cppview file →
void SuppressTransitions(HWND h) {
    if (!g_noTrans.insert(h).second) return;
    BOOL on = TRUE;
    DwmSetWindowAttribute(h, DWMWA_TRANSITIONS_FORCEDISABLED, &on, sizeof(on));
}

void RestoreTransitions() {
    BOOL off = FALSE;
    for (HWND h : g_noTrans) {
        if (IsWindow(h))
            DwmSetWindowAttribute(h, DWMWA_TRANSITIONS_FORCEDISABLED, &off, sizeof(off));
    }
    g_noTrans.clear();
}

void ApplyVisibility(const std::vector<HWND>& show, const std::vector<HWND>& hide) {
    for (HWND h : show) SuppressTransitions(h);
    for (HWND h : hide) SuppressTransitions(h);

    constexpr UINT kCommon = SWP_NOMOVE | SWP_NOSIZE | SWP_NOZORDER |
                             SWP_NOACTIVATE | SWP_NOOWNERZORDER | SWP_ASYNCWINDOWPOS;
    HDWP hdwp = BeginDeferWindowPos((int)(show.size() + hide.size()));
    for (HWND h : show) { if (hdwp) hdwp = DeferWindowPos(hdwp, h, nullptr, 0, 0, 0, 0, kCommon | SWP_SHOWWINDOW); }
    for (HWND h : hide) { if (hdwp) hdwp = DeferWindowPos(hdwp, h, nullptr, 0, 0, 0, 0, kCommon | SWP_HIDEWINDOW); }

    if (hdwp) EndDeferWindowPos(hdwp);
    else {
        for (HWND h : show) ShowWindowAsync(h, SW_SHOWNA);
        for (HWND h : hide) ShowWindowAsync(h, SW_HIDE);
    }
}

New windows are auto-assigned to the active namespace via two more WinEvent hooks — EVENT_OBJECT_SHOW and EVENT_OBJECT_DESTROY — rather than any polling loop:

Switchr/src/Namespaces.cppview file →
g_owner = hotkeyOwner;
g_showHook = SetWinEventHook(
    EVENT_OBJECT_SHOW, EVENT_OBJECT_SHOW,
    nullptr, ShowHookProc, 0, 0,
    WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS);
g_destroyHook = SetWinEventHook(
    EVENT_OBJECT_DESTROY, EVENT_OBJECT_DESTROY,
    nullptr, DestroyHookProc, 0, 0,
    WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS);

"Load and launch missing apps" (Ctrl+Shift+L) has to solve a timing problem: the process it just launched doesn't have a window yet, so its eventual window can't be assigned to a namespace synchronously. Instead the launch records a PendingAssign — expected exe name, target namespace, timestamp — with a two-minute TTL, and the next EVENT_OBJECT_SHOW for a matching exe consumes it and drops the entry if the launch never produced a window in time:

Switchr/src/Namespaces.cppview file →
// Apps launched by LoadApps join their saved namespace (not the active one)
// when their window finally appears; entries expire in case a launch dies.
struct PendingAssign {
    std::wstring exeLower;
    int          ns;
    ULONGLONG    tick;
};
std::vector<PendingAssign> g_pending;
constexpr ULONGLONG        kPendingTtlMs = 120 * 1000;

void PrunePending() {
    ULONGLONG now = GetTickCount64();
    g_pending.erase(
        std::remove_if(g_pending.begin(), g_pending.end(),
            [now](const PendingAssign& p) { return now - p.tick > kPendingTtlMs; }),
        g_pending.end());
}

The saved layout itself is a deliberately simple line-based UTF-8 format under %APPDATA%\Switchr\namespaces.txt:

Switchr/src/Namespaces.cppview file →
bool Ns::SaveToFile() {
    if (g_names.empty()) return false;

    std::vector<std::vector<std::wstring>> apps(g_names.size());
    for (auto& [hwnd, ns] : g_assign) {
        if (ns < 0 || ns >= (int)g_names.size() || !IsWindow(hwnd)) continue;
        std::wstring exe = GetWindowExePath(hwnd);
        if (!exe.empty()) apps[(size_t)ns].push_back(exe);
    }

    std::string data;
    for (size_t i = 0; i < g_names.size(); ++i) {
        data += "ns\t" + ToUtf8(g_names[i]) + "\n";
        for (const auto& a : apps[i]) data += "app\t" + ToUtf8(a) + "\n";
    }

    std::wstring path = ConfigFilePath();
    return !path.empty() && WriteFileBytes(path, data);
}

A ns<TAB>name line starts each namespace, and the following app<TAB>path lines — one per line, resolved by re-querying each managed window's exe path at save time rather than caching it — list its apps, with file order doubling as namespace order.

Per-monitor DPI, properly

The app manifest declares PerMonitorV2 DPI awareness (Switchr/app.manifest), and the overlay reads GetDpiForWindow both on creation and on WM_DPICHANGED, so dragging the overlay's owning monitor setup around — or just opening it on a monitor at a different scale than the last one — keeps every DIP constant measurement (tile size, gaps, font size) crisp instead of blurry or mis-scaled. The overlay itself always opens on the monitor of the current foreground window, resolved through MonitorFromWindow, not wherever the mouse cursor happens to be:

Switchr/src/Overlay.cppview file →
static RECT MonitorRectForForeground() {
    HWND fg = GetForegroundWindow();
    HMONITOR mon = fg ? MonitorFromWindow(fg, MONITOR_DEFAULTTOPRIMARY)
                      : MonitorFromPoint(POINT{ 0, 0 }, MONITOR_DEFAULTTOPRIMARY);

    MONITORINFO mi{ sizeof(mi) };
    GetMonitorInfoW(mon, &mi);
    return mi.rcMonitor;
}

No installer, no admin, one instance

The manifest requests asInvoker execution — Switchr never needs to elevate, which matters because a non-elevated Switchr can't AttachThreadInput to or activate a window owned by an elevated process, a real limitation the project accepts rather than asking users to run it as admin. A single named mutex enforces one running instance, and the whole thing ships as one exe with no install step — the tray icon and a RegisterHotKey global hotkey are the entire footprint on the running system.

The stack, in one place

  • C++17 directly on Win32 — no UI framework, no game engine.
  • Direct3D 11 + DirectComposition + Direct2D + DirectWrite for GPU-composited rendering, with server-side (compositor-thread) opacity animation.
  • DWM thumbnails (DwmRegisterThumbnail) for live tile previews instead of captured bitmaps.
  • WinEvent hooks (EVENT_SYSTEM_FOREGROUND, EVENT_OBJECT_SHOW/DESTROY) drive MRU tracking and namespace auto-assignment — no polling anywhere.
  • PerMonitorV2 DPI awareness declared in the app manifest, with live WM_DPICHANGED handling.
  • A hand-written multi-term search ranker (position-weighted, MRU-tiebroken) over window titles and exe names.
  • Plain line-based UTF-8 persistence for namespace layouts under %APPDATA% — no database, no serialization library.
  • asInvoker, single-instance via a named mutex, zero-install single exe.
