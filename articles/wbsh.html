wbsh

Technologies and approaches behind wbsh

wbsh is a Bash-compatible shell for Windows, written from scratch in C++17 as a drop-in replacement for Git Bash — without the MSYS2 layer underneath it. That means no POSIX-emulation DLL translating syscalls, a real shell-grammar front end instead of a regex approximation, and a single self-contained binary. Here's how the pieces fit together, with links straight to the source.

A real front end: lexer → parser → AST → expander

Input text goes through four distinct stages rather than one big string-munging pass. The lexer turns raw text into a token stream, but deliberately stops short of interpreting expansions — $(...), ${...}, $((...)) bodies are captured as raw text spans and handed to later stages, because getting their extents right (nested quotes, nested parens) is already the hard part: src/lexer.h#L1-L17. Heredocs are also resolved at this stage — the lexer remembers the delimiter and slurps lines until it's matched, before the parser ever sees them.

The parser builds an AST of tagged-union nodes (Node::Kind) rather than a class hierarchy with RTTI, because the executor dispatches on that tag with a plain switch instead of virtual calls: src/ast.h#L1-L20. Every node also carries a borrowed pointer into the original source text, so the executor can slice out the exact substring a construct was parsed from — used for self-spawned subshells and for reconstructing function bodies in declare -f output.

Finally the expander walks the AST's Word segments and turns them into real strings — glob expansion, parameter expansion, brace expansion, and command substitution all happen here, after parsing, not intermixed with it.

Bump-allocated ASTs: one arena, no per-node heap traffic

Every node the parser creates comes from an Arena — a bump-pointer allocator that hands out memory from 16 KB chunks instead of calling new per node. A whole parsed script costs a handful of chunk allocations instead of one malloc per AST node, and teardown is a single reverse pass over recorded destructors instead of a recursive ownership chain: src/arena.h#L1-L18. Pointers returned by Arena::make() (L50-L64) are deliberately raw and non-owning — the arena owns everything, nodes just borrow from it, which is what lets the AST have no vtables and no reference counting at all.

Control flow as a value, not an exception

break, continue, return, and exit don't unwind the C++ call stack via throw. They set a FlowSignal on the Executor — a plain struct with a kind, a status code, and a loop-nesting count for multi-level break N (src/executor.h#L36-L58). Every frame checks flowPending() (L286) after running a child node and returns early if a signal is live; the frame that actually owns the construct — the loop, the function call, the subshell, the top-level driver — is the one that calls consumeFlow() (L316) and stops the signal from propagating further. It reads like manual exception handling because that's exactly what it is, done explicitly so control flow stays visible in the executor's own logic instead of hiding in a C++ unwind.

POSIX ↔ Win32 path translation

PathConv is a Cygwin/MSYS-style mount table: /c/Users/... maps to C:\Users\..., /tmp maps to %TEMP%, /dev/null maps to NUL, and so on, with both directions being idempotent so re-translating an already-native path is a no-op: src/pathconv.h#L58-L106. When wbsh spawns a native argument, it only translates the ones that look like they need it — starts with /, isn't a flag, isn't a URL, isn't a bare / — and for --opt=PATH-style arguments it translates just the value side: src/pathconv.cpp#L346-L379.

Two subtler problems live in the same file. First, MSVC's std::filesystem::path(std::string) interprets narrow strings through the active codepage, not UTF-8, so a name like "Tomáš" silently mangles into mojibake on disk unless every path is round-tripped through a wide string first — the reason utf8ToPath / pathToUtf8 exist at all (src/pathconv.h#L1-L20). Second, when wbsh hands HOME to a MinGW-built child (Git for Windows and friends), that child's ANSI getenv reads the environment block through the same active codepage and can mangle non-ASCII usernames the same way — so toWin32Short() converts to the legacy 8.3 short path (C:\Users\TOMA~1), which is pure ASCII and survives any transcoding, falling back to the long form only when the path is already ASCII or the volume has 8.3 name generation disabled: src/pathconv.cpp#L248-L291.

Line editing: ghost-text prediction that knows what failed

The interactive line editor implements PowerShell-style inline prediction: as you type, the rest of the best-matching history entry is rendered as dim text past the cursor, and → at the end of the line accepts it. The matching function scans history newest-first for the first entry that starts with the typed prefix — but skips any entry whose last execution exited non-zero, via a parallel exit-status vector, so a typo you already made once never gets re-suggested: src/lineedit.h#L61-L84.

Reverse-incremental search (Ctrl-R) is a small pure function over the same history vector — scan backward or forward from a start index for the first entry containing the query as a substring — which keeps the search logic testable independent of the raw-mode console loop that drives it (src/lineedit.h#L40-L56). On a real console the editor runs a raw-mode loop with cursor movement, kill ring, and Unicode-aware redraw; on piped stdin (scripts, tests) it transparently falls back to a line-buffered read loop, so the same binary drives both an interactive TTY and wbsh -r script.sh < input without a separate code path for either.

Fitting into a real Windows console

Rather than drawing its own terminal, wbsh enables ENABLE_VIRTUAL_TERMINAL_PROCESSING on the console's output mode so ANSI escape sequences render natively in conhost, Windows Terminal, VS Code, and JetBrains terminals, and only falls back to plain output if that mode can't be set (src/repl.cpp#L463-L466). It also paints its own console window to match: DwmSetWindowAttribute flips on immersive dark mode and tints the caption and border to the shell's palette on Win11, falling back to the pre-1903 dark-mode constant and silently ignoring the caption/border calls on older systems that don't support them (src/repl.cpp#L84-L99).

Bundled coreutils, one binary

ls, grep, sed, awk, find, xargs, tar, gzip, curl, and a few dozen more are implemented directly in the shell binary rather than shelled out to separate executables — the coreutils sources alone (coreutils.cpp, coreutils_text.cpp, awk.cpp, and siblings for archives, hashing, and bc-style arithmetic) run to several thousand lines. That's what makes a fresh install scriptable immediately, with no MSYS DLL, no Cygwin layer, and nothing extra to fetch — the resulting exe is roughly 1 MB, and the installer adds only the VC++ runtime on top of it. System tools like git, vim, and less are still auto-discovered on PATH and invoked as native processes when present; wbsh only replaces the layer that used to require MSYS.

Testing: the suite is written in wbsh, run by wbsh

The 44-plus-script test suite isn't driven by an external test runner — it's a wbsh script (tests/run-all.sh) that wbsh -r executes, which in turn runs every other .sh file in the directory through the same shell. It checks exit codes against expectations and, in golden mode, diffs combined stdout+stderr against recorded fixtures under tests/expected/ (tests/run-all.sh#L1-L22), with a small deny-list of scripts excluded from golden comparison because their output is inherently machine-specific (dates, hostnames, native command output). Every run of the suite is itself exercising the parser, the expander, functions, control flow, and the bundled coreutils — the shell testing itself with itself.

The stack, in one place

  • C++17, no external shell-parsing library — hand-written lexer, recursive-descent parser, AST, and expander.
  • Arena / bump allocation for AST nodes: no per-node heap allocation, no vtables, no reference counting.
  • Control flow (break/continue/return/exit) modeled as an explicit signal value, not C++ exceptions.
  • PathConv: a Cygwin/MSYS-style mount table for POSIX↔Win32 path translation, plus UTF-8-safe filesystem path handling and 8.3 short-path fallback for MinGW children.
  • A raw-mode line editor with persistent history, kill ring, tab completion, reverse-incremental search, and failure-aware inline prediction.
  • Native console integration via ENABLE_VIRTUAL_TERMINAL_PROCESSING and DWM immersive dark mode — no bundled terminal emulator.
  • Dozens of bundled coreutils compiled directly into the binary — no MSYS/Cygwin layer, ~1 MB executable.
  • A 44-script golden test suite written in and executed by wbsh itself.
