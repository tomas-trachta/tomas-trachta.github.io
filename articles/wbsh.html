wbsh

Technologies and approaches behind wbsh

wbsh is a Bash-compatible shell for Windows, written from scratch in C++17 as a drop-in replacement for Git Bash — without the MSYS2 layer underneath it. That means no POSIX-emulation DLL translating syscalls, a real shell-grammar front end instead of a regex approximation, and a single self-contained binary. Here's how the pieces fit together, with real snippets from the source (trimmed for length; // … marks an elision).

A real front end: lexer → parser → AST → expander

Input text goes through four distinct stages rather than one big string-munging pass. The lexer turns raw text into a token stream of operators and words:

src/lexer.hview file →
enum class TokKind {
    Word,            // generic word; reserved words detected at parse time
    IoNumber,        // digits immediately followed by '<' or '>' (no space)
    Newline,
    EndOfInput,

    AndIf,           // &&
    OrIf,            // ||
    DSemi,           // ;;
    SemiAmp,         // ;&     (bash, fall-through case terminator)
    DSemiAmp,        // ;;&    (bash)
    Semi,            // ;
    Amp,             // &
    Pipe,            // |
    PipeAmp,         // |&     (bash, equivalent to 2>&1 |)
    LParen,          // (
    RParen,          // )

    Less,            // <
    Great,           // >
    DLess,           // <<
    // …
};

Reserved words aren't separate token kinds — if, for, and friends all come back as a plain Word and get recognized later, at parse time, from their raw text. The bodies of $(...), ${...}, $((...)) are captured as raw text spans and handed to later stages, because getting their extents right (nested quotes, nested parens) is already the hard part. Heredoc bodies are also captured here: when a << operator and its delimiter word are seen, the lexer remembers the delimiter and, on the next newline, slurps lines until the delimiter is matched.

The parser builds an AST of tagged-union nodes (Node::Kind) rather than a class hierarchy with RTTI, because the executor dispatches on that tag with a plain switch instead of virtual calls. Every node also carries a borrowed pointer into the original source text, so the executor can slice out the exact substring a construct was parsed from — used for self-spawned subshells and for reconstructing function bodies in declare -f output:

src/ast.hview file →
struct Node {
    enum class Kind {
        SimpleCommand,  ///< `simple_command` — words + assignments + redirs.
        Pipeline,       ///< `cmd | cmd | cmd` (with optional `!` and `time`).
        AndOr,          ///< `cmd && cmd` / `cmd || cmd`.
        List,           ///< Sequence of `cmd ;` or `cmd &` items.
        IfClause,       ///< `if … then … [elif …] [else …] fi`.
        WhileClause,    ///< `while …` / `until …`.
        ForClause,      ///< `for var [in words]; do …; done`.
        // …
    };
    Kind kind;                  ///< Concrete subclass tag.
    SourceLoc loc;              ///< Position in the source.
    std::size_t src_start = 0;  ///< Inclusive byte offset in source.
    std::size_t src_end   = 0;  ///< Exclusive byte offset in source.
    const std::string* source_text = nullptr;  // borrowed, arena-owned
    explicit Node(Kind k) : kind(k) {}
};

struct SimpleCommand : Node {
    SimpleCommand() : Node(Kind::SimpleCommand) {}
    std::vector<Assignment> assignments;
    std::vector<Word> words;
    std::vector<Redirection> redirs;
};

Every concrete node type derives from Node and sets its own Kind in the constructor; the executor's dispatch is then a plain switch (node->kind) that static_casts to the concrete type it already knows the tag implies — no dynamic_cast, no vtable lookup. src_start/src_end/source_text are what let the executor slice the original text for self-spawned subshells and for reconstructing function bodies in declare -f output; source_text is a borrowed pointer into a copy interned in the same Arena that owns the node, so keeping the arena alive keeps the whole tree — and its source — valid.

Finally the expander walks the AST's Word segments and turns them into real strings — glob expansion, parameter expansion, brace expansion, and command substitution all happen here, after parsing, not intermixed with it.

Bump-allocated ASTs: one arena, no per-node heap traffic

Every node the parser creates comes from an Arena — a bump-pointer allocator that hands out memory from 16 KB chunks instead of calling new per node. A whole parsed script costs a handful of chunk allocations instead of one malloc per AST node, and teardown is a single reverse pass over recorded destructors instead of a recursive ownership chain:

src/arena.hview file →
/**
 * @file arena.h
 * @brief Bump-pointer memory arena for node-heavy structures (ASTs).
 *
 * Objects are allocated by bumping an offset inside large chunks, so a
 * whole tree costs a handful of mallocs instead of one per node, nodes
 * sit contiguously in memory, and teardown is one pass instead of a
 * recursive ownership-pointer chain. Destructors of non-trivially-
 * destructible objects are recorded at make() time and run (in reverse
 * allocation order) when the arena is destroyed — so members like
 * std::string / std::vector inside arena objects release normally.
 *
 * Arenas are move-only: whoever holds the Arena owns every object ever
 * made from it. Pointers returned by make() are stable for the arena's
 * lifetime and are deliberately raw — they are borrows, not owners.
 */

template <typename T, typename... Args>
T* make(Args&&... args) {
    // Chunks come from new[] and are aligned to the default new
    // alignment; over-aligned types would need aligned chunks.
    static_assert(alignof(T) <= alignof(std::max_align_t),
                  "Arena does not support over-aligned types");
    void* mem = allocate(sizeof(T), alignof(T));
    T* obj = new (mem) T(std::forward<Args>(args)...);
    if constexpr (!std::is_trivially_destructible_v<T>) {
        dtors_.push_back({ obj, [](void* p) {
            static_cast<T*>(p)->~T();
        } });
    }
    return obj;
}

Pointers returned by Arena::make() are deliberately raw and non-owning — the arena owns everything, nodes just borrow from it, which is what lets the AST have no vtables and no reference counting at all.

Control flow as a value, not an exception

break, continue, return, and exit don't unwind the C++ call stack via throw. Each builtin just sets a FlowSignal on the Executor — a kind, a status code, and a loop-nesting count — and returns normally:

src/builtins.cppview file →
static int builtin_break(Executor& exec, const std::vector<std::string>& args) {
    if (exec.loopDepth() == 0) {
        printerr("break: only meaningful in a `for', `while', or `until' loop");
        return 0;
    }
    exec.raiseBreak(firstArgAsInt(args, 1, /*require_positive=*/true));
    return 0;
}

static int builtin_continue(Executor& exec, const std::vector<std::string>& args) {
    if (exec.loopDepth() == 0) {
        printerr("continue: only meaningful in a `for', `while', or `until' loop");
        return 0;
    }
    exec.raiseContinue(firstArgAsInt(args, 1, /*require_positive=*/true));
    return 0;
}

Every frame checks flowPending() after running a child node and returns early if a signal is live. The loop body's epilogue is where a multi-level break N actually gets consumed one level at a time as the unwind passes through each enclosing loop:

src/executor.cppview file →
LoopFlowAction Executor::dispatchLoopFlow() {
    switch (flow_.kind) {
    case FlowSignal::Kind::Continue:
        if (--flow_.count > 0) return LoopFlowAction::Propagate;
        clearFlow();
        return LoopFlowAction::NextIter;
    case FlowSignal::Kind::Break:
        if (--flow_.count > 0) return LoopFlowAction::Propagate;
        clearFlow();
        return LoopFlowAction::ExitLoop;
    case FlowSignal::Kind::Return:
    case FlowSignal::Kind::Exit:
        return LoopFlowAction::Propagate;
    case FlowSignal::Kind::None:
    default:
        return LoopFlowAction::Normal;
    }
}

break 3 decrements the count once per enclosing loop it passes through and only actually exits the loop whose turn it is; every loop above it sees Propagate and keeps unwinding. It reads like manual exception handling because that's exactly what it is, done explicitly so control flow stays visible in the executor's own logic instead of hiding in a C++ unwind.

POSIX ↔ Win32 path translation

PathConv is a Cygwin/MSYS-style mount table: /c/Users/... maps to C:\Users\..., /tmp maps to %TEMP%, /dev/null maps to NUL, and so on, with both directions being idempotent so re-translating an already-native path is a no-op:

src/pathconv.cppview file →
PathConv::PathConv() {
    for (char c = 'a'; c <= 'z'; ++c) {
        Mount m;
        m.posix = std::string("/") + c;
        std::string w; w += static_cast<char>(std::toupper(static_cast<unsigned char>(c)));
        w += ":";
        m.win32 = std::move(w);
        m.exact = false;
        mounts_.push_back(std::move(m));
    }

    std::string tmp = getTempDir();
    if (!tmp.empty()) mounts_.push_back({ "/tmp", tmp, false });

    mounts_.push_back({ "/dev/null", "NUL", true });
    mounts_.push_back({ "/dev/tty",   "CON",     true });
    mounts_.push_back({ "/dev/stdin", "CONIN$",  true });
    mounts_.push_back({ "/dev/stdout","CONOUT$", true });
    mounts_.push_back({ "/dev/stderr","CONOUT$", true });
}

Translation itself is a longest-prefix match over that table — /c and a hypothetical /c/temp mount would both match /c/temp/x, and the longer one wins:

src/pathconv.cppview file →
bool PathConv::applyMount(const std::string& p, std::string& out) const {
    const Mount* best = nullptr;
    std::size_t best_len = 0;
    for (const auto& m : mounts_) {
        if (m.exact) {
            if (p == m.posix) { best = &m; best_len = m.posix.size(); break; }
            continue;
        }
        if (p.size() < m.posix.size()) continue;
        if (p.compare(0, m.posix.size(), m.posix) != 0) continue;
        if (p.size() > m.posix.size() && p[m.posix.size()] != '/') continue;
        if (m.posix.size() > best_len) { best = &m; best_len = m.posix.size(); }
    }
    if (!best) return false;
    // … stitch best->win32 with the remaining tail, flipping slashes …
    return true;
}

When wbsh spawns a native argument, it only translates the ones that look like they need it — starts with /, isn't a flag, isn't a URL, isn't a bare / — and for --opt=PATH-style arguments it translates just the value side:

src/pathconv.cppview file →
bool PathConv::argLooksTranslatable(const std::string& arg) const {
    if (arg.empty()) return false;
    if (arg == "/") return false;
    if (arg.find("://") != std::string::npos) return false;
    if (arg[0] == '-') return false;
    if (arg[0] != '/') return false;
    // Single-letter `/x` is almost always a Win32-style switch (`cmd /c`,
    // `cmd /k`, `where /q`, etc.). Require a deeper path before we
    // translate, OR an exact match against a known mount.
    if (arg.size() < 3) return false;
    if (arg.size() >= 4 && arg[2] == '/') return true;
    // …
    std::string out;
    return applyMount(arg, out);
}

std::string PathConv::translateArg(const std::string& arg) const {
    if (argLooksTranslatable(arg)) return toWin32(arg);
    if (!arg.empty() && arg[0] == '-') {
        std::size_t eq = arg.find('=');
        if (eq != std::string::npos && eq + 1 < arg.size()) {
            std::string val = arg.substr(eq + 1);
            if (argLooksTranslatable(val)) {
                return arg.substr(0, eq + 1) + toWin32(val);
            }
        }
    }
    return arg;
}

Two subtler problems live in the same area of the codebase. First, MSVC's std::filesystem::path(std::string) interprets narrow strings through the active codepage, not UTF-8, so a name like "Tomáš" silently mangles into mojibake on disk unless every path is round-tripped through a wide string first — the reason utf8ToPath / pathToUtf8 exist at all (src/pathconv.h's file-level comment documents the mechanism in full). Second, when wbsh hands HOME to a MinGW-built child (Git for Windows and friends), that child's ANSI getenv reads the environment block through the same active codepage and can mangle non-ASCII usernames the same way — so toWin32Short() converts to the legacy 8.3 short path (C:\Users\TOMA~1), which is pure ASCII and survives any transcoding, falling back to the long form only when the path is already ASCII or the volume has 8.3 name generation disabled:

src/pathconv.cppview file →
std::string PathConv::toWin32Short(const std::string& p) const {
    std::string longw = toWin32(p);
#ifdef _WIN32
    if (longw.empty()) return longw;
    bool has_non_ascii = false;
    for (unsigned char c : longw) {
        if (c >= 0x80) { has_non_ascii = true; break; }
    }
    if (!has_non_ascii) return longw;

    // … convert UTF-8 → wide, call GetShortPathNameW, convert back to UTF-8 …

    // If 8.3 generation is off on this volume, GetShortPathName returns
    // the long form unchanged — still non-ASCII, still mangleable.
    // Fall back to the long form (caller is no worse off than before).
    for (unsigned char c : out) {
        if (c >= 0x80) return longw;
    }
    return out;
#else
    return longw;
#endif
}

Line editing: ghost-text prediction that knows what failed

The interactive line editor implements PowerShell-style inline prediction: as you type, the rest of the best-matching history entry is rendered as dim text past the cursor, and → at the end of the line accepts it. The matching function scans history newest-first for the first entry that starts with the typed prefix — but skips any entry whose last execution exited non-zero, via a parallel exit-status vector, so a typo you already made once never gets re-suggested:

src/lineedit.cppview file →
std::string findInlinePrediction(const std::vector<std::string>& history,
                                 const std::vector<int>& history_status,
                                 const std::string& prefix) {
    if (prefix.empty()) return {};
    for (std::size_t i = history.size(); i > 0; --i) {
        const std::size_t idx = i - 1;
        if (idx < history_status.size() && history_status[idx] != 0) continue;
        const std::string& entry = history[idx];
        if (entry.size() > prefix.size()
            && entry.compare(0, prefix.size(), prefix) == 0) {
            return entry.substr(prefix.size());
        }
    }
    return {};
}

Reverse-incremental search (Ctrl-R) is a small pure function over the same history vector — scan backward or forward from a start index for the first entry containing the query as a substring — which keeps the search logic testable independent of the raw-mode console loop that drives it:

src/lineedit.cppview file →
std::size_t findReverseSearchMatch(const std::vector<std::string>& history,
                                   const std::string& query,
                                   std::size_t start_index,
                                   bool forward) {
    if (query.empty() || history.empty()) return history.size();
    std::size_t start = start_index < history.size()
        ? start_index : history.size() - 1;
    if (forward) {
        for (std::size_t i = start; i < history.size(); ++i) {
            if (history[i].find(query) != std::string::npos) return i;
        }
        return history.size();
    }
    // Backward (toward older entries). i is unsigned, so guard the
    // underflow by walking until i hits 0 and then breaking after the
    // final compare.
    for (std::size_t i = start;; --i) {
        if (history[i].find(query) != std::string::npos) return i;
        if (i == 0) break;
    }
    return history.size();
}

On a real console the editor runs a raw-mode loop with cursor movement, kill ring, and Unicode-aware redraw; on piped stdin (scripts, tests) it transparently falls back to a line-buffered read loop, so the same binary drives both an interactive TTY and wbsh -r script.sh < input without a separate code path for either.

Fitting into a real Windows console

Rather than drawing its own terminal, wbsh enables ENABLE_VIRTUAL_TERMINAL_PROCESSING on the console's output mode so ANSI escape sequences render natively in conhost, Windows Terminal, VS Code, and JetBrains terminals, and only falls back to plain output if that mode can't be set:

src/repl.cppview file →
// The captured "good" modes are re-applied before every prompt:
// externals (pagers, vim) corrupt console state and don't restore it.
s.h_out = GetStdHandle(STD_OUTPUT_HANDLE);
s.h_in  = GetStdHandle(STD_INPUT_HANDLE);
if (s.h_out != INVALID_HANDLE_VALUE && GetConsoleMode(s.h_out, &s.good_out_mode)) {
    s.good_out_mode |= ENABLE_VIRTUAL_TERMINAL_PROCESSING;
    s.good_out_mode |= ENABLE_PROCESSED_OUTPUT;
    s.good_out_mode |= ENABLE_WRAP_AT_EOL_OUTPUT;
    s.color_ok = SetConsoleMode(s.h_out, s.good_out_mode) != 0;
}

It also paints its own console window to match: DwmSetWindowAttribute flips on immersive dark mode and tints the caption and border to the shell's palette on Win11, falling back to the pre-1903 dark-mode constant and silently ignoring the caption/border calls on older systems that don't support them:

src/repl.cppview file →
static void setupConsoleWindow() {
    SetConsoleTitleW(L"wbsh");
    HWND hwnd = GetConsoleWindow();
    if (!hwnd) return;
    BOOL dark = TRUE;
    if (FAILED(DwmSetWindowAttribute(hwnd, DWMWA_USE_IMMERSIVE_DARK_MODE,
                                     &dark, sizeof(dark)))) {
        DwmSetWindowAttribute(hwnd, DWMWA_USE_IMMERSIVE_DARK_MODE_OLD,
                              &dark, sizeof(dark));
    }
    // Win11-only: paint the caption + frame to match the shell's dark
    // theme. Older systems return E_INVALIDARG, which we silently ignore.
    COLORREF caption = RGB(0x14, 0x14, 0x18);
    DwmSetWindowAttribute(hwnd, DWMWA_CAPTION_COLOR, &caption, sizeof(caption));
    COLORREF border = RGB(0x33, 0x33, 0x3a);
    DwmSetWindowAttribute(hwnd, DWMWA_BORDER_COLOR, &border, sizeof(border));
}

Bundled coreutils, one binary

ls, grep, sed, awk, find, xargs, tar, gzip, curl, and a few dozen more are implemented directly in the shell binary rather than shelled out to separate executables — the coreutils sources alone (coreutils.cpp, coreutils_text.cpp, awk.cpp, and siblings for archives, hashing, and bc-style arithmetic) run to several thousand lines. That's what makes a fresh install scriptable immediately, with no MSYS DLL, no Cygwin layer, and nothing extra to fetch — the resulting exe is roughly 1 MB, and the installer adds only the VC++ runtime on top of it. System tools like git, vim, and less are still auto-discovered on PATH and invoked as native processes when present; wbsh only replaces the layer that used to require MSYS.

Testing: the suite is written in wbsh, run by wbsh

The 44-plus-script test suite isn't driven by an external test runner — it's a wbsh script that wbsh -r executes, which in turn runs every other .sh file in the directory through the same shell. It checks exit codes against expectations and, in golden mode, diffs combined stdout+stderr against recorded fixtures under tests/expected/:

tests/run-all.shview file →
run_one() {
    local script=$1
    local out=$TMP_DIR/${script}.out

    "$WBSH" -r "$script" > "$out" 2>&1
    local rc=$?

    if [ "$rc" -eq 0 ]; then
        printf "  ok       %s\n" "$script"
    else
        printf "  FAIL rc  %s (got %d, want 0)\n" "$script" "$rc"
        FAIL_COUNT=$((FAIL_COUNT + 1))
        return
    fi

    if [ "${WBSH_GOLDEN:-0}" = "1" ] && ! is_in_list "$script" "$NO_GOLDEN"; then
        if diff -u "$GOLDEN_DIR/${script}.out" "$out" > "$TMP_DIR/${script}.diff" 2>&1; then
            printf "           golden ok\n"
        else
            printf "  FAIL out %s -- diff in %s/${script}.diff\n" "$script" "$TMP_DIR"
            FAIL_COUNT=$((FAIL_COUNT + 1))
        fi
    fi
}

with a small deny-list of scripts excluded from golden comparison because their output is inherently machine-specific (dates, hostnames, native command output). Every run of the suite is itself exercising the parser, the expander, functions, control flow, and the bundled coreutils — the shell testing itself with itself.

The stack, in one place

  • C++17, no external shell-parsing library — hand-written lexer, recursive-descent parser, AST, and expander.
  • Arena / bump allocation for AST nodes: no per-node heap allocation, no vtables, no reference counting.
  • Control flow (break/continue/return/exit) modeled as an explicit signal value, not C++ exceptions.
  • PathConv: a Cygwin/MSYS-style mount table for POSIX↔Win32 path translation, plus UTF-8-safe filesystem path handling and 8.3 short-path fallback for MinGW children.
  • A raw-mode line editor with persistent history, kill ring, tab completion, reverse-incremental search, and failure-aware inline prediction.
  • Native console integration via ENABLE_VIRTUAL_TERMINAL_PROCESSING and DWM immersive dark mode — no bundled terminal emulator.
  • Dozens of bundled coreutils compiled directly into the binary — no MSYS/Cygwin layer, ~1 MB executable.
  • A 44-script golden test suite written in and executed by wbsh itself.
